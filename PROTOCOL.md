# Declared protocol — 14 October 2026

Practical question: can a small local document-search tool preserve inspectable source evidence, distinguish unsupported fixture queries and export the same results users see?

Contribution: authored Python API/CLI and local browser app, deterministic passage/source identifiers, line spans and document hashes, ranked lexical evidence and JSON/CSV export. Established lexical retrieval; no generative answers, novel algorithm, deployment or SOTA claim.

Inputs: eight authored synthetic business/engineering Markdown documents. Code and authored fixtures: MIT. No customer, employer or personal data. Corpus/query files are saved and hashed. Two development queries for debugging are separate from 16 relevant and six unsupported evaluation fixtures. The author can see all fixtures; results are functionality/retrieval fixture tests, not independent scientific validation. No claim of realistic enterprise prevalence.

Preset configuration, declared before execution: paragraph segmentation with at most eight source lines/passage, no overlap; scikit-learn 1.4.2 TfidfVectorizer with word unigrams, English stop words, Unicode accent stripping, default two-character token pattern, smooth IDF and L2 normalisation. Vocabulary/IDF fit on document passages only, never query labels. Dot product ranks TF-IDF vectors. Retain positive matches with score at least 0.15. Baseline is the fraction of unique analysed query tokens present in each passage, accepting any positive score. These different score scales/thresholds are explicitly declared, not calibrated to equal acceptance. Ties use source ID then first line. k=3. No score/probability/entailment equivalence.

Primary results: source recall at 1 and 3 for the 16 queries with a declared relevant source; accepted/rejected irrelevant counts for the six unsupported queries; rejected relevant-query count; complete saved ranks, source lines/hashes, overlaps and scores. Report raw numerators/denominators, all methods and failures. Lexical near-miss queries intentionally expose possible unsupported acceptance; do not suppress these errors or tune the threshold using final fixtures. No runtime comparison or confidence interval planned.

Checks: invalid/duplicate IDs, empty/oversized/tokenless corpus, empty/oversized query, Unicode/punctuation, all-zero query vectors, score finiteness and bounds, unchanged inputs, deterministic ties, exact source line/hash mapping, k/threshold validation, no query-vocabulary leakage, structured output, JSON/CSV round trips and spreadsheet formula neutralisation. Run CLI examples and HTTP user workflow/error/export tests. For the browser: actual search/no-evidence workflow, keyboard focus/labels, responsive phone layout, escaped source text and exact displayed/exported values.

Availability: local-only. Bind to 127.0.0.1, no external assets or model calls, no API keys. Text file import is processed on this machine; no third-party transmission. The minimal development server is not production hosting. Limits: English lexical features, short curated fixtures, weak synonym/negation/numeric reasoning, fixed uncalibrated gate, human verification still required.

Save configuration, sources, dependency versions, commands, stdout, fixture/query hashes, actual predictions/results and three editable static figures. A defect repair during implementation is recorded; if evaluation-driven changes occur, label reruns exploratory. GitHub publication and native LinkedIn duplicate/audience/image checks precede the final action.
