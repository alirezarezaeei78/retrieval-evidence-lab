# Implementation corrections and scope

The first protocol checksum check stopped before evaluation because the frozen receipt describes UTF-8/LF text while Windows stored CRLF. The runner now checks normalized protocol text against that unchanged declaration. The initial traceback is retained privately in the publication package; no model setting, fixture, label or threshold was changed.

The initial browser Blob-download click did not yield a verifiable download event. The app now streams the already saved JSON/CSV text through a same-origin bounded POST form and fixed Content-Disposition filename. No fitting or reranking happens on export, no temporary source files are saved server-side and Host/Origin checks still apply. Both original single-search exports and batch exports use that transport. Earlier download behavior is not claimed verified.

A Chrome internal-download-history URL was rejected by browser policy; it was not retried or accessed by another mechanism. Verification uses only the app's ordinary HTTP download controls and the documented download event API.

New source/index/request hashes are versioned separately from the legacy single-search corpus hash. Source snapshots canonicalize document order; index hash includes the explicit configuration, fitted vocabulary/IDF, sparse passage matrix and scikit-learn version. A snapshot hash identifies the declared payload; it is not a certificate of semantic correctness or a guarantee of cross-version byte identity.

Browser numeric observations rounded one score by one binary-float ULP in tool transport. The audit therefore compares exact rendered decimal strings and CSV/JSON files; all79scores and ranks agree. No retrieval score was changed.

The390px viewport override was requested, but DOM measured1920px after reload and a fresh tab. It was reset. Desktop behavior and native downloads are verified; mobile-device behavior remains unverified. No browser-policy denial was bypassed.
